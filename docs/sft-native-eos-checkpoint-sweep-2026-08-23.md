# Динамика native-EOS SFT по чекпоинтам — 2026-08-23

## Протокол

- модель: `Qwen/Qwen2.5-1.5B`;
- SFT: OpenMathInstruct-2, 296k source limit, одна эпоха, 4 593 шага;
- LoRA: `r=32`, `alpha=64`, dropout `0.05`, `all-linear`;
- optimizer: fused AdamW, LR `2e-4`, cosine decay, warmup 138 шагов,
  effective batch size 64;
- формат policy: общий plain-text math prompt и native EOS `<|endoftext|>`;
- eval: full-split greedy vLLM, batch size 768, `max_new_tokens=2048`;
- checkpoints: 500, 1000, ..., 4500; финальный шаг 4593 приведён для сравнения.

## Наблюдения

1. **Обучение почти сошлось к шагу 4000.** Между 4000 и 4593 validation loss меняется
   всего на `-0.000289`, а accuracy — на +0.61 п.п. GSM8K, +0.66 п.п. GSM1K,
   +0.18 п.п. MATH и +0.35 п.п. MMLU-STEM.
2. **Checkpoint-4500 практически эквивалентен final.** Относительно 4593 он отличается на
   -0.08 п.п. GSM8K, +0.25 п.п. GSM1K, -0.02 п.п. MATH и -0.06 п.п. MMLU-STEM.
3. **MATH улучшается наиболее последовательно:** 42.66% на шаге 500 против 45.64% в финале.
   Одновременно truncation падает с 796 до 547, средняя длина — с 593 до 507 токенов,
   а parse rate растёт с 83.76% до 88.62%.
4. **GSM8K делает основной скачок после 2500:** 72.02% → 74.53% на шаге 3000, затем
   продолжает плавно расти до 75.66%.
5. **GSM1K шумнее validation loss:** лучший промежуточный результат — 70.54% на шаге 3000,
   что на 0.66 п.п. выше final. Это укладывается в обычный benchmark noise и не является
   основанием выбирать checkpoint-3000.
6. **MMLU-STEM не улучшается по мере math-SFT.** Метрика колеблется около 41–42%, а минимум
   40.44% совпадает с шагом 3000. Падение относительно прежнего ChatML SFT не вызвано
   переобучением в конце эпохи: оно присутствует уже на checkpoint-500.
7. **Native EOS работает с ранних шагов.** На GSM8K/GSM1K truncation остаётся около 1–2%,
   а на MATH качество остановки постепенно улучшается. Финальная модель не демонстрирует
   прежнее массовое продолжение после правильного ответа.

## Вывод

Для этой конфигурации стоит сохранять финальный checkpoint-4593: он лучший или статистически
эквивалентен лучшему на трёх math benchmarks и имеет минимальный validation loss. Early stopping
около шага 4000 мог бы сэкономить примерно 13% optimizer steps почти без потери качества, но это
следует подтверждать по заранее выделенному validation benchmark, а не выбирать задним числом по
GSM8K/GSM1K/MATH/MMLU test splits.

Все checkpoint test eval здесь являются ретроспективным анализом. Использовать лучший test
checkpoint для production selection нельзя без test leakage; для следующих запусков нужен
отдельный development set с тем же generation protocol.
